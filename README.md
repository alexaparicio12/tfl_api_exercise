

## Introduction

This is the code for an app which connects to the TFL public API and finds any disruptions or relevant status updates for lines at a provided time.

This has been built in approximately 6 hours, and is relatively limited when it comes to the display. Outputs are also not saved in a data store yet.

### Functionality
The endpoints supported are:
- GET /health: simple status check
- GET /disruptions?lines=a,b: proxy to TFL Disruption API for given line IDs
- POST /tasks: create/schedule a task. Body should be: {"lines":"victoria,central", "scheduler_time":"YYYY-MM-DDTHH:MM:SS"}. If scheduler_time is empty, this defaults to now. task_id is autogenerated if not provided. If the scheduler_time is set to before now, the task runs now.
- GET /tasks: lists all tasks (includin the results when they have been run)
- GET /tasks/task_id: fetches a specific task
- PATCH /tasks/task_id: updates scheduler_time and/or lines for an existing task
- DELETE /tasks/task_id: deletes a task and cancels it scheduled job


There is an option to provide scheduled tasks through a csv, but this is work in progress to illustrate how the design would evolve if a database were available. By default, any tasks saved in the tasks.csv file in the data folder are added to the app tasks.

The format for schedule times will be: '%Y-%m-%dT%H:%M:%S', or 'HH:MM' defaulting to today. Time is in local timezone (of requester and server).

If an empty `schedule_time` is sent, schedule a task to run immediately.

The valid line IDs are:
```
[
    "bakerloo",
    "central",
    "circle",
    "district",
    "elizabeth",
    "hammersmith-city",
    "jubilee",
    "metropolitan",
    "northern",
    "piccadilly",
    "victoria",
    "waterloo-city",
    "dlr",
    "liberty",
    "lioness",
    "mildmay",
    "suffragette",
    "weaver",
    "windrush"
]
```
## API usage (curl)

- Create a task (run now if `scheduler_time` empty, `task_id` auto-generated):
  ```
  curl -X POST http://localhost:5555/tasks \
    -H "Content-Type: application/json" \
    -d '{"lines":"victoria,central","scheduler_time":"2024-05-01T08:30:00"}'
  ```

- List tasks:
  ```
  curl http://localhost:5555/tasks
  ```

- Get a task (includes result after it runs):
  ```
  curl http://localhost:5555/tasks/<task_id>
  ```

- Update time and/or lines (either field optional, at least one required):
  ```
  curl -X PATCH http://localhost:5555/tasks/<task_id> \
    -H "Content-Type: application/json" \
    -d '{"scheduler_time":"2024-05-01T09:00:00","lines":"victoria,central"}'
  ```

- Delete a task:
  ```
  curl -X DELETE http://localhost:5555/tasks/<task_id>
  ```

## Running the sample Flask app with Docker

Build the image:

```
docker build -t tfl-api-exercise .
```

Run the container (exposes port 5555):

```
docker run --rm -p 5555:5555 tfl-api-exercise
```
The container entrypoint runs `python -m src.app`.

Check the health endpoint:

```
curl http://localhost:5555/health
```

## Scheduling from CSV

Tasks in `data/tasks.csv` (columns: `task_id,lines,schedule_time`) are loaded automatically on startup. `schedule_time` may be full ISO (`2024-05-01T08:30:00`), `HH:MM` for today, or empty to run immediately.

Example `data/tasks.csv`:

```
task_id,lines,schedule_time
1,"victoria","20:30"
2,"bakerloo,jubilee",""
```

## Scheduling TFL disruption fetches

Create a scheduled task (ISO time `YYYY-MM-DDTHH:MM:SS`):

```
curl -X POST http://localhost:5555/tasks \
  -H "Content-Type: application/json" \
  -d '{"lines":"victoria,central","scheduler_time":"2024-05-01T08:30:00"}'
```

List tasks:

```
curl http://localhost:5555/tasks
```

Fetch a single task (includes result after it runs):

```
curl http://localhost:5555/tasks/morning-run
```

Delete a task:

```
curl -X DELETE http://localhost:5555/tasks/morning-run
```

## User guide

- **Launch the app locally (no Docker):**
  ```
  python3 -m venv .venv
  source .venv/bin/activate
  pip install -r requirements.txt
  python -m src.app
  ```
  Then check: `curl http://localhost:5555/health`.

- **Run tasks from `data/tasks.csv`:** ensure the file has `task_id,lines,schedule_time` columns. On app start, rows are auto-loaded and scheduled. `schedule_time` may be ISO (`YYYY-MM-DDTHH:MM:SS`), `HH:MM` (today), or empty to run immediately. View loaded tasks/results: `curl http://localhost:5555/tasks`.

- **Add a new task via POST:** (app must be running)
  ```
  curl -X POST http://localhost:5555/tasks \
    -H "Content-Type: application/json" \
    -d '{"lines":"victoria,central","scheduler_time":"2024-05-01T08:30:00"}'
  ```
  `scheduler_time` is optional (empty runs now). `task_id` is auto-generated if omitted.
